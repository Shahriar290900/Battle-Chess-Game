# Decisions

| # | Decision | Why |
|---|---|---|
| 1 | **Web first** (Vite + TS + three.js), shipped as GitHub Pages site **and** an Android debug APK via Capacitor 7. | One codebase for PC browser, phone browser, APK. |
| 2 | **Modes:** vs Computer (Stockfish 19 lite single-thread WASM in a Worker; Easy/Medium/Hard/Master) and local **pass-and-play** 2-player. No online play. | Single-thread build needs no SharedArrayBuffer/COOP/COEP, so it runs on Pages and in the APK WebView. GPL is fine: personal, non-commercial project. |
| 3 | **No Blender/Unity.** Assets come from a Python "code forge" (`tools/forge/`, numpy + Pillow) writing contract-v1 GLBs; turntables rendered by headless three.js (Playwright). | Machine has no DCC tools. Result is a stylised painted-miniature look, not sculpted. |
| 4 | **Original IP only.** Factions Emberhold (White) vs Rime Host (Black) with art-bible names. No franchise names, crests or sculpt references in the repo. | Skill ground rule 1; repo is public. |
| 5 | **Music:** user's MP3 is copied to `public/audio/theme.mp3` by `npm run prepare-music` and is **gitignored**. Public Pages build has no theme; players can load their own track (IndexedDB). Local + APK builds include it. | Repo is public; avoid redistributing a copyrighted track. |
| 6 | **SFX are procedural** (WebAudio synthesis) — no sample files. | Code-only, zero licensing. |
| 7 | **Facing:** pieces face the enemy. Emberhold rest yaw = π (faces −z), Rime rest yaw = 0 (faces +z). GLB front is +Z. | Battle-chess staging; the skill text's "faces White" note was ambiguous. |
| 8 | **Node 20** toolchain: Vite 7.3.7, Vitest 4.1.11, TS 5.9.3, Capacitor 7.6.9 (Vitest 5 / Capacitor 8 need Node 22). `.npmrc legacy-peer-deps=true` (npm 10 arborist peer bug). All versions published before 2026-10-07. | Avoid changing the machine's Node. |
| 9 | **Quality tiers:** High (desktop dGPU), Medium (default desktop/iGPU), Low (mobile/APK: LOD1, no transmission, 1024 shadows, 120 particles, no SMAA). Auto-picked by 2 s benchmark + `isMobile`. | Budget: 60 fps Medium on iGPU; captures ≥ 30 fps. |
| 10 | Contract v1 per skill `references/asset-pipeline.md` §1; TS mirror in `src/contracts/`. Module boundaries in `src/contracts/apis.ts`. Only the lead edits `src/contracts/**`. | Parallel agents code against interfaces. |
| 11 | Camera default **Follow turn** in pass-and-play, **Fixed to my side** vs AI. | Architecture §7. |
| 12 | Base path: `./` for local/Capacitor, `/Battle-Chess-Game/` for Pages (`BASE_PATH` env). Assets referenced relative to `import.meta.env.BASE_URL`. | Same build works in both hosts. |
| 13 | GLBs live in `public/models/` (served as-is by Vite, copied into the APK). Forge writes there directly. | No copy step, one source of truth. |
| 14 | **Browser = Brave.** Automation: Playwright `chromium.launch({ executablePath: '/Applications/Brave Browser.app/Contents/MacOS/Brave Browser', headless: true, timeout: 180000 })` (temp profile; cold start ~60 s, so launch once per script). Showing the user: `open -a "Brave Browser" <url>` (new tab in their running Brave). Bundled Playwright browsers are unsupported on macOS 12. | User preference. |
| 15 | **Contract v1.1** (additive): optional `Taunt` clip (check provoke); `GraphicsSettings` + `GRAPHICS_PRESETS` (adjustable graphics: resolution scale, shadows, bloom, AA, particles, physics, ambient, secondary motion, FPS); `FxApi.setGraphics/setStaticActors`; `PostPipeline.setGraphics`; `KinematicsApi` (src/kinematics: spring bones, look-at, lean, knockback); `AttractMode` (launch cinematic + background duels behind menu). | User feature request 2026-10-22. |
| 16 | **UI direction (supersedes the minimal restyle):** skeuomorphic medieval-wood "physical objects with digital displays": main menu = wooden bookshelf of books, HUD = carved wood + brass device with a retro LCD/VFD display, settings = hi-fi style panel with knobs/switches. Crafted textures, not glow/gradient clichés. | User request 2026-10-22. |
| 17 | **Contract v1.2** (additive): `GraphicsSettings.fpsCap` 30/60/0(unlimited); `Settings.tutorialSeen`; optional `Surrender` clip + optional `weapon` bone (checkmate: king kneels, losing pieces drop weapons); events `clash`, `weapon:drop`, `debris:impact`, `taunt`, `surrender`, `loading:progress`; SFX names for clash/drop/debris/taunt/kneel and physical-UI sounds. | User request 2026-10-22. |
| 18 | **Learn area** (`src/learn/**`, new owner `learn`): first-launch guided intro + "How to Play" interactive lessons on the 3D board (one per piece + check, castling, en passant, promotion, mate, beginner tactics) + Piece Library (orbit/zoom inspector, names/roles/moves, live mini-duel loop side view). | User choices 2026-10-22. |
| 19 | **Agent cost policy:** Sonnet only for forge/engine/cinematics/vfx/kinematics/learn; Haiku for qa, art-director, ai-opponent, platform-audio, monitor and helpers. Max 3 build agents at once. Global Sonnet effort = medium. Scheduled Haiku monitor every ~20 min. | /usage: general-purpose subagents were 83% of usage. |
| 20 | **UI direction v3 (supersedes 16):** dark gothic AAA UI per user references (kept OUT of the repo: commercial screenshots). Performance target: ≥50–60 fps Medium on Intel HD 6000-class iGPU; auto-quality detects weak GPUs. | User feedback 2026-10-23 (10 fps, dark board, buggy buttons). |
| 21 | **Process hygiene:** agents may only terminate processes they started (track PIDs / `browser.close()`); never `pkill -f "Brave Browser"` or similar broad kills — the user browses in Brave. | vfx agent closed the user's Brave on 2026-10-23. |
