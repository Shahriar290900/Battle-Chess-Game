# Unity Port (optional)

The same GLBs and the same contract drive a Unity build. Map the web pieces like this:

| Web | Unity |
|---|---|
| GLTFLoader + KTX2/meshopt | **glTFast** package (import at edit time; KTX2 via its KTX add-on, meshopt via its meshopt add-on) |
| chess.js | a C# rules library or a port; keep the same perft tests in an EditMode test assembly |
| AnimationMixer clips | Animator Controller per role with states `Idle/Move/Attack/HitReact/Victory`; or Playables for code-driven scrubbing |
| GSAP timelines | **Timeline** assets per choreography (signal emitters at `impact`), or DOTween sequences for code-built ones |
| cameraRig spherical tween | **Cinemachine**: one virtual camera per seat + shot cameras with blend curves; Impulse for shake |
| rapier debris | PhysX rigidbodies on fragment children, pooled |
| particle pool | VFX Graph (URP/HDRP) or Particle System for mobile |
| hit-stop | `Time.timeScale` with unscaled UI/camera blends |
| extras (`impactTime` …) | glTFast imports extras only through a custom import hook; simplest is a sidecar `pieces.json` generated by `validate_glb.py --json` |

Coordinate note: glTF is right-handed Y-up, Unity is left-handed Y-up; glTFast converts
by flipping X, so +Z front stays front. Re-check socket positions after import.

C#/Unity specifics: one `PieceActor : MonoBehaviour` holding Animator, sockets
(`Transform` lookups by name), extras from the sidecar; `CaptureDirector` as an async
(UniTask or coroutine) orchestrator mirroring the label skeleton in capture-choreography.md.
